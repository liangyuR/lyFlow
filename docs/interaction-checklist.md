# 交互清单

自建节点编辑器的真实风险不在功能，在**交互细节的长尾**。连线吸附手感、对齐参考线、多选批量移动、
连线中途松手弹搜索面板、断开连线时另一端跟随鼠标……成熟编辑器打磨了很多年，
用户会下意识觉得理所应当，缺了就觉得"这软件很粗糙"。

这份清单的用途是：**在动工前就知道总共要补多少项**，而不是做到一半才发现还有二十项。

对照基准：ComfyUI（节点图易用性）、Blender Geometry Nodes（编辑器手感）。
「RF」列表示 React Flow 是否白送。

## 工作量估计

| 分档 | 内容 | 估计 |
|---|---|---|
| 便宜（几百行内） | 拓扑排序+环检测、端口类型校验、序列化、状态高亮、类型着色 | 各几十到一两百行 |
| 中等 | 参数表单动态生成、撤销重做、复制粘贴、节点搜索面板 | 每项 1–3 天 |
| 贵 | 子图、live preview、大图性能 | 各一周以上，可延后 |

## 验收方式

每完成一档，找一个没参与开发的人，给他一句话任务（"把这个 pcd 降采样后去平面，看结果"），
不做任何讲解，观察他卡在哪。卡住的地方基本都能对应到上表里某个没做的项。

**M1–M4 的实际做法**：不写前端单元测试（CLAUDE.md），改为用 CDP 驱动真实运行的
Tauri app 断言。脚本在 [`scripts/e2e/`](../scripts/e2e/)，`pnpm e2e` 一条命令跑完：
M2 的分组在 `run.mjs`，M3 的在 `m3.mjs`，M4 的在 `m4.mjs`，页面侧动作共用 `page.mjs`。
覆盖演示 pipeline、错误定位、取消、中文路径（stale 与 Run to node 两组 2026-09-26 精简时并入 m3 / noderun），M3 的
缓存复用、静音透传、迁移、连线手感与布局，以及 M4 的子图、库算子、live preview、大图性能。
headless CLI 没有界面，它的验收在 `bridge/src/cli.rs` 的 `cargo test` 里。

这套验证在 M1 抓到三个真 bug、M2 抓到两个、M3 抓到四个、M4 抓到六个（见
[m4-acceptance.md](m4-acceptance.md)），没有一个是单元测试能发现的 ——
它们全都要求真实的浏览器、真实的事件和真实的后端。**尤其是拖拽类的项**：
#17/#19/#21 的断言必须用 CDP 的 Input 域发真鼠标事件，还得先把节点按屏幕坐标摆好，
否则测到的是「元素在不在 DOM 里」而不是「手感对不对」。
