# 参数面板与参数配方 —— 实施计划

目标：**一张 flow 的全部参数在一个大面板里看得全、改得动（14 种参数类型都有控件）；同一张 flow 可以切换参数配方，配方存在独立文件里。**

前提与出处：调研和讨论结论见 [param-recipe-research.md](param-recipe-research.md) §7（D1–D6）；设计稿是 2026-09-24 对话里的三屏稿（按节点、配方矩阵、配方管理），用户已同意。
使用者只有工程师，不分级（D3）。

分四期，**每期一个子代理、一个 commit、一份验收记录**（`docs/param-recipe-pN-acceptance.md`），我独立验收通过后才开下一期。

## 0. 全局定死的决定

| # | 决定 | 理由 |
|---|---|---|
| K1 | **配方的结构 = 顶层图参数**。配方 = `{ 图参数名: 值 }` 的稀疏覆盖，只有一层；没写的参数用图参数的 `default`（称为「基础」） | D1；限位、校验、cacheKey、CLI、C ABI 全部沿用一套 |
| K2 | **任何节点参数都可以一键「纳入配方」= 提升为图参数**：当前的有效值成为 `default`，节点上的显式值删除，加一条 bind。子图内部的参数做逐层提升链（内部 → 子图参数 → 这个实例上绑成图参数），**一个动作、一次撤销**；同一子图的其它实例以当前值作默认值，行为不变。库算子（`lib.`）内部只读 | D6；不引入第二套覆盖机制 |
| K3 | **运行时由编辑器合成参数**：`default + 当前配方覆盖` 得到 `{名字: 值}`，经 `RunOptions.params` 传给 core（C ABI 已经有 `params_json`）。core 不知道配方的存在。切换配方不改 GraphDoc、不进 GraphDoc 的撤销；结果缓存按内容寻址，切回原来的配方就是命中缓存 | D5 |
| K4 | **总是从基础重新计算**：有效值 = `default` 叠加当前配方，不叠加在上一个配方之上 | 调研：MERLIC 的反例 |
| K5 | **校验合并后的有效值**：实时校验（validate）也带上 `params`，所以诊断反映的是当前配方的值；当前配方有 error 时不能运行 | 调研：Helm |
| K6 | **编辑语义**（用户已同意）：① 选着配方时，改一个已纳入配方的参数，写进**当前配方**；想改基础就切到「基础」，或者对这一行点「写回基础」。② 选着配方时，改一个没纳入配方的参数，照常改图，这一行提示「此改动影响所有配方」，并给一个「改为只在本配方生效」（= 纳入配方，再把新值写进当前配方）。③ Ctrl+S 一次保存图和所有有改动的配方文件；工具栏的脏标记合并显示；切换配方不弹窗，未保存的改动留在内存里，不会丢 | Houdini Takes 的逻辑；不让人丢改动 |
| K7 | **配方的改动进同一个撤销栈**：撤销记录同时快照 GraphDoc 与内存中的配方集合；切换当前配方本身不算一步撤销 | Ctrl+Z 的直觉只有一种 |
| K8 | 只给工程师用：不做权限、操作员视图、审批、版本管理、配方继承 | D3、D5 |

## P1 —— 图参数成形（core、schema、编辑器 store、运行传参）

| # | 决定 |
|---|---|
| P1.1 | **图参数声明扩成完整参数规格**：`graph-doc.schema.json` 的顶层 `params` 每项在现有 `{type?, default, binds, doc?}` 基础上，允许 manifest 参数声明的全部字段（`label`、`min/max/softMin/softMax/step/unit`、`options`、`group`、`advanced`、`placeholder`、`filters/mode`、`componentLabels`、`semantic`/`roiBackdrop` 等，schema 里尽量 `$ref` 复用 manifest 的定义，不抄一份）。老文件完全兼容。编辑器「纳入配方」时，从被绑定目标的 manifest 声明**复制规格**（包括 `label`，默认写成「节点标题 · 参数 label」） |
| P1.2 | **core 校验图参数的值**：`default` 和经 `params_json` 传进来的值，先按图参数自己的规格校验（类型、硬限位、options），不合法时报 `bad_param`，`paramPath` 为图参数名、`nodeId` 为空；然后照旧走被绑定节点的参数规整。声明里没有 `type` 的老图参数，跳过第一步 |
| P1.3 | **编辑器 graph store 的图参数动作**：`promoteToGraphParam(nodeId, param)`（含子图内部参数的提升链，K2）、`bindToGraphParam`、`unbindFromGraphParam`（把当前值写回节点，行为不变）、`removeGraphParam`（同上，写回所有绑定目标）、`renameGraphParam`、`setGraphParamDefault`、`setGraphParamSpec`。都是一次撤销 |
| P1.4 | **Inspector 与参数显示合并绑定值**：被图参数绑定的参数显示图参数的有效值（K3 的合成结果），行上标「由图参数 X 提供」；在这一行编辑，会路由到图参数（按 K6 写进配方或 default），**不再写成节点上的显式值，`param_conflict` 的陷阱消失** |
| P1.5 | **`RunOptions.params` 贯通**：`Transport.runGraph` 与 `validate` 的选项加 `params?: Record<string, unknown>`；Tauri、HTTP、Static 三个 transport，bridge（Tauri 命令与 HTTP 信封）传到 C ABI 的 `params_json`；`packages/editor/test-server` 的桩服务器转成 CLI 的 `--param`。实时预览同样带上 |
| P1.6 | **顺手修**：「复制路径名」带上 nodeId（`节点.参数`）；`visibleWhen/enabledWhen` 的 `ne` 在 schema、core、编辑器三方一致（core 补上 `ne`）；撤销回到保存点时 dirty 复原 |

**P1 验收**（doctest、cargo test、e2e 分组 `scripts/e2e/params_p1.mjs`）

1. schema：带完整规格的图参数通过；老格式通过；`graph-doc` 往返（Rust 与编辑器）不丢任何新字段。
2. core：`default` 越过图参数的硬限位报 `bad_param`（`paramPath` = 名字）；`params_json` 传入越界值同样报错；老的无 `type` 图参数照常运行。
3. 编辑器：对普通节点参数「纳入配方」→ doc 里出现图参数（规格从 manifest 复制，default = 当前值），节点显式值被删，运行结果与纳入前逐位相同（cacheKey 不变，或结果相同）；一次 Ctrl+Z 完全还原。
4. 子图内部参数纳入配方：出现子图参数 + 图参数两级；同一子图的另一个实例运行结果不变；一次撤销还原两级。库算子内部参数不提供该动作。
5. 在被绑定参数的行上编辑：doc 里改的是图参数的 `default`，不产生 `param_conflict`。
6. 用 `RunOptions.params` 传一个与 default 不同的值运行：被绑定节点的 cacheKey 与结果跟着变；再传回 default，命中缓存。
7. P1.6 三项各一条断言。
8. 不回归：`pnpm check`；带 `LYFLOW_PACKS=gap;dts` 的 `pnpm e2e` 全绿（输出落盘，grep「未验」「跳过」）；`pnpm e2e:http` headless 全绿。

## P2 —— 参数面板（按节点）与全部类型控件

| # | 决定 |
|---|---|
| P2.1 | **面板形态**（D4）：画布右侧的大面板，与画布并排、同时可见；可拖宽（记住宽度），可最大化（画布收起，再点还原）。工具栏「参数」按钮与快捷键 `Ctrl+Shift+P` 开关。打开时替代 Inspector；画布上选中节点，面板滚动定位到该节点并高亮；面板里点节点标题，画布选中并居中该节点 |
| P2.2 | **三个页签**：按节点、配方矩阵、配方管理（后两个在 P3 填内容，P2 先放占位）|
| P2.3 | **按节点页**：顶部「图参数」分组（所有图参数，可编辑规格：label、限位、单位、group；可解除绑定、删除），然后按「当前层级的节点，子图可展开进它的定义 → group」列出所有参数。advanced 组默认折叠（修掉现在「不折叠」的问题）；`visibleWhen` 不满足的参数隐藏，`enabledWhen` 不满足的置灰 |
| P2.4 | **每一行**：label（改过的有蓝点，= 与算子默认不同）、控件、右侧图标（恢复、纳入配方的书签：空心 = 可纳入，实心 = 已纳入）。右键菜单沿用现有的（重置、复制值、粘贴值、复制 `节点.参数` 路径、提升）。子图定义里的参数，节点标题旁标「子图定义 · N 个实例共享」；库算子内部参数只读 |
| P2.5 | **搜索与过滤**：搜索参数名、label、节点标题、节点 id、值的文本；过滤 chip：全部 / 已改动 / 已纳入配方 / 有诊断 / 按类型。计数实时显示 |
| P2.6 | **全部 14 种类型的控件**：复用 `ParamControls` 现有的 12 种；新增 **transform**（平移 xyz + 旋转 xyz（度），可切换显示为 4×4 矩阵；存储格式照 manifest 现有约定）和 **curve**（控制点列表 + 小画布拖拽编辑，按 manifest 的 curve 值格式）。控件在面板和 Inspector 里是同一份实现 |
| P2.7 | **ROI 参数**：行内缩略图（框在底图上的位置示意），点开进入现有的 2D 拖框视图，拖动写回同一参数 |
| P2.8 | **诊断**：带 `paramPath` 的诊断贴在对应行下；图参数的诊断（`nodeId` 为空）贴在「图参数」分组对应行下 |
| P2.9 | **性能**：行列表虚拟化；1000 个参数的图打开面板 < 300ms，滚动不掉帧（≥ 50fps），输入一个数字到画布状态更新 < 100ms |
| P2.10 | **全类型示例**：新增一个测试算子（放在现有测试算子所在的位置，只在测试 / e2e 构建里注册）声明 14 种类型各至少一个参数，含 group、advanced、visibleWhen、enabledWhen、roi；`examples/` 加一张用它的示例图，作为 P2、P3 的验收素材 |

**P2 验收**（e2e 分组 `scripts/e2e/params_p2.mjs`）

9. 面板开关、拖宽、最大化与还原、宽度记忆；打开时 Inspector 不显示；画布选中 ↔ 面板定位双向联动。
10. 全类型示例图：14 种类型每种的控件都能改值，改完 doc 中值正确、类型正确；transform 与 curve 的往返（改 → 保存 → 重开）值不变。
11. advanced 默认折叠；visibleWhen/enabledWhen 随另一个参数的改动即时生效。
12. 搜索与每个过滤 chip 的结果正确（对着 doc 计算的期望值断言）。
13. 子图定义行有共享标记，改它影响所有实例（两个实例的有效值都变）；库算子内部只读。
14. ROI 缩略图点开进入拖框视图，拖动后参数变化，一次撤销还原。
15. 性能：用脚本生成 1000 参数的图，满足 P2.9 的三个阈值。
16. 不回归，同 P1 第 8 条。

## P3 —— 配方

| # | 决定 |
|---|---|
| P3.1 | **配方文件**：`<名字>.lyflow-recipe.json`，schema `schema/recipe.schema.json`：`{ schemaVersion, name, graph: { id, specDigest }, values: { 图参数名: 值 }, note?, updatedAt }`。`graph.id` 取 GraphDoc 的 `id`；`specDigest` 是图参数规格（名字、类型、限位、options）的规范化摘要。默认目录是图文件同目录的 `<图文件名去扩展名>.recipes/`；目录下可选 `index.json`：`{ default?: 名字, order?: [名字…] }` |
| P3.2 | **transport 的配方文件接口**：列目录、读、写、删除、重命名，Tauri 与 HTTP 都实现；Static transport 只读。未保存的新图（没有路径）不能建配方，提示先保存 |
| P3.3 | **工具栏配方下拉框**：「基础」+ 各配方 + 「新建配方…」；有未保存改动显示脏标记（图与配方合并，K6③）。打开图时，有 `index.json.default` 就选它，否则选「基础」 |
| P3.4 | **编辑语义照 K6**，撤销照 K7。被当前配方覆盖的行：左侧橙色竖条 + 「配方 · 基础 X」标签，行内「恢复基础」（删掉这条覆盖）、「写回基础」（把值写进 default，删掉覆盖）|
| P3.5 | **配方矩阵页**：行是图参数（按 group 分组），列是「基础」+ 各配方（当前配方标 ●）；单元格三态：沿用基础（灰字，不存）、配方存的值（橙）、越界或非法（红，悬停写原因）；单元格可直接编辑（按该参数的控件，复杂值弹出编辑）；可「只显示差异」；可多选单元格，复制到指定配方；列可以隐藏 |
| P3.6 | **配方管理页**：列表（名字、值个数、失配数、默认星标）；新建（空，或复制当前配方）、复制、重命名、删除（确认）、设为默认、导入（复制外部配方文件进目录，重名时让用户改名）、导出（另存到任意位置）；右侧为选中配方的详情与**失配报告** |
| P3.7 | **失配报告的四类**：① 多出：配方里的名字在图参数里不存在（→ 删除该值）；② 类型不符：值的类型与规格不符（→ 可转换时给转换建议，否则删除）；③ 越界/非法：不满足限位或 options（→ 夹到限位 / 改为默认）；④ 规格变了：`specDigest` 或 `graph.id` 与当前图不一致（提示，不阻止）。「全部按建议修复」一次撤销。有 ①–③ 的配方不能运行，其余配方不受影响 |
| P3.8 | 切换配方：有效值立刻按 K4 重算；stale 判定与「将重算 N 个节点」提示随之更新；autoRun 打开时照常触发运行 |

**P3 验收**（doctest/cargo 覆盖 schema 与摘要，e2e 分组 `scripts/e2e/params_p3.mjs`）

17. 新建两个配方、各改几项、Ctrl+S：磁盘上两个配方文件与 `index.json` 内容正确（只存与基础不同的值），图文件同时保存；重开后下拉框、矩阵、值都还原。
18. K6 ① ② ③ 各一条：选着配方改已纳入的参数 → 只有该配方文件变；改未纳入的 → 图变且行上有提示，「改为只在本配方生效」后图的该参数变成图参数、值只在当前配方；切换配方后回来，未保存的改动还在。
19. K4：配方 A 覆盖 x、配方 B 覆盖 y；A → B 后 x 回到基础（不残留 A 的值）。
20. 切换配方后运行：被覆盖参数影响的节点重算、其余命中缓存；切回原配方，全部命中缓存。
21. K7：配方值的改动能 Ctrl+Z / Ctrl+Y；切换配方不产生撤销记录。
22. 矩阵：三态显示正确；只显示差异；单元格编辑写对配方；多选复制到另一配方；越界单元格为红且该配方运行被阻止、给出原因。
23. 失配：手工构造的配方文件分别触发四类，报告条目与建议正确；「全部按建议修复」后可以运行，一次撤销还原。
24. 管理：新建、复制、重命名、删除、设为默认、导入（重名处理）、导出，各一条断言（磁盘结果）。
25. 不回归，同 P1 第 8 条。

## P4 —— CLI、MCP、宿主接入

| # | 决定 |
|---|---|
| P4.1 | CLI `run`、`validate`、`plan`、`params`、`eval`、`patch` 加 `--recipe <文件>`：读配方文件，合成图参数值；与 `--param` 叠加，`--param` 优先。失配 ①–③ 时退出码 4，stderr 打印失配报告（与编辑器同一套判定，逻辑放在 bridge 的 Rust 里，编辑器与 CLI 共享一份实现的话更好；做不到时两边各实现，同一组测试夹具）|
| P4.2 | MCP：`run_graph` 与 `get_params` 加 `recipe`（配方文件路径）参数；新增只读工具 `list_recipes`（列出图旁配方目录里的配方与失配摘要）。不提供写配方的工具 |
| P4.3 | 文档：`docs/embedding.md` 写宿主如何按名字切换配方（读配方文件 → `params_json`，失配检查怎么做，推荐的产线切换流程）；`docs/graph-doc.md` 补图参数的完整规格；新增 `docs/recipe.md` 描述文件格式、目录约定、四类失配；`packages/editor/README.md`、`docs/interaction-checklist.md` 登记 |

**P4 验收**

26. `lyflow run --recipe A.lyflow-recipe.json` 的结果等于编辑器选配方 A 运行的结果（同一张图、同一组样本，逐位比较 flush/gap 输出）；`--param` 覆盖配方中的同名值。
27. 失配的配方文件：CLI 退出码 4，stderr 列出条目；`validate --recipe` 同样。
28. MCP：`run_graph` 带 `recipe` 能跑且结果与 CLI 一致；`list_recipes` 返回正确；`packages/mcp` 的测试覆盖。
29. 不回归，同 P1 第 8 条；`pnpm check` 覆盖新增的 cargo 与 MCP 测试。

## 不做

权限与操作员视图；版本、审批、审计；配方继承；eval 按配方批量评估；多人同时编辑配方的冲突合并（文件被外部修改时，只在保存前检测并提示「文件已被外部修改」，让用户选择覆盖或重新载入）。
