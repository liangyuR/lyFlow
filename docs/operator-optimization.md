# 算子稳定性与性能优化

本轮改动包含运行时缓存、结果读取、ONNX 缓冲管理和可选 ICP 增强。代码基于 1.2 开发主分支，
产品版本和 C ABI 跟随主分支，本次未另外调整。

## 第一轮：缓存身份和资源生命周期

- Path 参数的缓存键追加按图目录解析的规范化绝对路径，避免不同目录下同名、同大小、同时间戳文件误用结果。
- 不可变 Tensor 的统计只计算一次，浅拷贝共享 min/max/mean，各份 Data 单独保留预览 scale。
- ONNX 会话使用最多 8 个缓存引用的 LRU；活跃调用通过 shared_ptr 保活。同一路径的新指纹加载成功后移出旧指纹。
- 会话构建串行去重，与缓存命中的短临界区分离；淘汰资源在缓存条目锁外释放。

文件内容仍以 size/mtime 指纹失效。同一路径保留元数据覆盖内容时应显式清理缓存或使用冻结输入。
缓存持有数量不等于进程内存硬上限：活跃调用和 ONNX Runtime 内存池也会保留资源。

## 第二轮：结果读取与推理输入缓冲

`reuse`、`outputsOf`、`outputInfo` 在结果仓锁内取得不可变载荷快照，在锁外完成统计、JSON 和 Bundle 字段展开。
同一次查询使用完整快照，保持端口顺序和精确端口优先级；查询不写回索引，不恢复已被 freeRun/clear 删除的运行。

每个 ONNX 会话复用 CPU MemoryInfo 和输入缓冲，同一会话的输入复制、推理、输出复制仍串行执行。
保留输入只读约定，并在锁内复制可能别名输入的输出，避免并发覆盖。缓冲按历史最大容量保留至会话释放，
因此减少分配次数的同时会增加空闲会话的驻留内存；不表示输入数据已经零拷贝。

推理输出只接受 float32，读取前检查 ONNX 元素类型、形状和元素数量，非 float32 返回明确诊断。
允许形状一致的零元素输出，不解引用空地址。Tensor 形状乘法检查溢出，负维度和溢出不能伪装成有效空输入。

## 第三轮：可选鲁棒多尺度 ICP

`register.icp_2d` 增加可选鲁棒损失、粗到细配准和最终位姿质量门，具体参数和结果字段见
[标准点云包](../packs/std-pointcloud/README.md)。默认使用原来的最小二乘、单尺度路径，质量评估和拒绝门默认关闭。
gap 包直接调用共享算法时沿用原默认选项。

鲁棒损失降低大残差配对的影响；多尺度先用稀疏云估计初值，再逐层细化，最后使用原始点云与原配对阈值。
质量统计按最终位姿重新建立配对，仅在显式请求或启用质量门时执行，避免给默认调用追加一次全量近邻扫描。
启用质量门后，不满足匹配数、内点比例、残差或收敛要求的结果返回诊断，可由图中的 fallback 分支处理。

默认开关兼容不等于已证明数值等价或性能改善，新增路径需要使用业务样本确定尺度、阈值和误差界。

## 验证范围与交付

[第一轮历史记录](operator-stability-round1-acceptance.md)对应同步最新主分支之前的代码，包含缓存冲突反证、全包测试和 Tensor 元信息微基准。
按用户要求，第二、三轮与同步主分支后的最终代码未运行本地构建、单测、性能基准或现场回放。
新增回归用例随 PR 提交，留待后续执行；历史通过结果不能作为最终修订的验证结论。

建议后续先执行带标准包、glue、gap 的 core 测试及生成式 ONNX 夹具，再针对实际图和工件样本检查有效量测率、误检漏检、
量测容差、缓存未命中/命中时的整图 p95、吞吐与峰值内存。发布仍遵循[发包规则](deployment/packaging.md)。
