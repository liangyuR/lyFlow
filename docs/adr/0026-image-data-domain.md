# ADR-0026：图像是一个独立的数据类型，按「级别 + 行」取出

- 状态：已采纳
- 日期：2026-09-29

## 背景

第二个数据域（roadmap「M5 之后」）要回答两个问题：图像在数据模型里是什么，以及它怎么过 IPC。
计划与调研见 [image-plan.md](../image-plan.md)。可供参照的是两条已有的路：

- `Tensor`（ADR-0015 / ADR-0019）：只有 float32，零拷贝按元素切片，不抽稀；
- 点云（ADR-0006）：复制 + 等步长抽稀。

## 决策

1. **`Data::Kind::Image` 是新的一种，不复用 `Tensor`。** 端口类型只有一个 `Image`，
   通道数（1 / 3 / 4）与位深（u8 / u16 / f32）是运行时属性。
2. **布局**：行主序、通道交错（HWC）、**行紧排**、**RGB(A) 顺序**。
   像素是别名构造的 `shared_ptr<const uint8_t>`，所有者可以是任何东西。
3. **取数（C ABI v15）**：`lyflow_output_image(run, node, port, level, rowOffset, rowCount, view)`。
   - level 0 是原图、零拷贝借用；
   - level k 是 2^k 倍**块均值**缩小（尺寸向上取整），core 现算一份；
   - 按行切片，越界是空切片；
   - 桥接层按 16 MB 收行数。
4. **宿主注入**：另开 `lyflow_run_image_input` 挂在 run options 末尾，允许带行填充的缓冲。
5. **契约**：`shape` 与 `finite` 放开给图像，形状按 `[高, 宽, 通道]` 读。**不开第五种键**。

## 理由

**为什么不复用 Tensor。**
- 一张 500 万像素的 RGB 图用 u8 存是 15 MB，转成 float 是 60 MB。
- 相机与 PNG 给的就是 u8 / u16，转一遍 float 再转回去纯属浪费。
- 更要紧的是类型本身在说话：特征图不该不经转换就接进二值化。

图像进推理要走显式的 `image.to_tensor`，归一化、mean/std、HWC → NCHW 都是看得见的参数。

**为什么只有一个 `Image` 类型。** 分成 `ImageGray` / `ImageRGB` 有两个结果，都不好：
- 要么逼出隐式转换（`castableTo`）；
- 要么每个算子为每种通道写一份。

点云的可选通道是同一个道理（core/README「可选通道而非独立类型」）。
要灰度图的端口用契约 `shape: [-1, -1, 1]` 声明，接错时报 `contract_violation`，带期望与实际。

**为什么是 RGB 而不是 OpenCV 的 BGR。** 公共模型只反映本项目自己的抽象（ADR-0005）。
- canvas、PNG、绝大多数模型都是 RGB；
- BGR 只在 OpenCV 的 adapter 里出现，读写文件那一层转一次。

**为什么别名 `shared_ptr` 而不是 `std::vector<uint8_t>`。**
- 别名指针的 deleter 可以持有 `cv::Mat` 的引用计数，OpenCV 的结果零拷贝交给 core，而 core 一个 OpenCV 头都不 include。
- `vector` 做不到：每出一次 OpenCV 就得多拷一份整图。

**为什么缩小可以，而 ADR-0019 说张量不抽稀。**
- ADR-0019 反对的是**隔行取样**，那样得到的是另一张图。
- 块均值是离远了看同一张图：每个输出像素是它覆盖的那一块的均值，没有像素被丢掉。

看图的人先要全貌，再放大到 1:1 看细节。前者用缩小的一级，后者按可视行取原图，两者都不必一次搬整张大图。

**为什么契约复用 `shape` 而不开 `channels`。**
- ADR-0024 刻意只有四种键，理由是挡住表达式语言的诱惑。
- 图像的形状本来就是 HWC，`[-1, -1, 1]` 与张量的 `[2, -1, 1280]` 同一种写法，读的人不用多学一种。

## 代价

- **ABI 号跳到 15**。都是纯增量：新入口 + run options 末尾加字段，老符号不动。
- **HTTP 桩只给 level 0**。
  - 桩按请求起 CLI，`lyflow dump … .lyim` 取整张图再按行切，缩小那一步在桩里不做。
  - 帧头的 `level` 照实写 0，调用方本来就必须按帧头解释尺寸。
- **像素统计每次写出都算一遍**（valueJson 的逐通道 min/max/mean），与 Tensor 相同。
  2000 万像素约几十毫秒，比一次 IPC 便宜。
- **2D 几何的单位**：图像算子会输出像素单位的 Box2D / Circle2D，而这些类型原先注释写死「米」。
  决定是值里带 `unit`（image-plan Q2 选 a），实施在第一个输出几何的图像算子（阶段 2）。

## 不做

- 相机内参、像素到世界的变换进数据模型：深度图转点云时内参是那个算子的参数，出现第二个需要它的算子再议。
- 图像的抽稀预览（隔行取样）：见上。
- core 里的图像编解码器：PNG / JPEG 归 `std-image` 包（OpenCV），core 只写自己的 `.lyim`。
