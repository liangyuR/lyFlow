# ADR-0023：`patch` 是幂等的结构编辑，dry-run 与形状校验是它的前提

日期：2026-09-17（M6）　状态：已采纳并实现（`lyflow patch`、MCP `patch_graph`）

## 背景

第二次真实任务（xyz-gap-inspector 上带 11 个 fallback 的多点位调参，见 [m6-plan.md](../m6-plan.md) §来源）里，
所有**结构**实验都是这么做的：把数据库里的图复制一份，手改 JSON，再跑。为此写了两个 Python 脚本。

手改 JSON 的问题不在于「麻烦」，在于**没有回执**：

- 删一个节点要同时删它的所有边，漏一条就是一张悬空边的图，报出来的错在别处。
- 「我以为我改了」与「我真的改了」分不开 —— 脚本跑完只知道文件被写了，不知道写了什么。
- 同一个脚本跑第二遍会做第二次改动（再删一次、再插一次），所以不敢重跑，只能每次从干净副本开始。
- 改完之后到底有没有踩到别的东西（图级输出、单连接输入口），要跑一次才知道。

`--set` 只能改参数。M5 的 `perturb` 已经在 bridge 里做过图手术（在某个端口后插一个节点、
把该端口的所有下游改接到新节点上），证明这件事该由平台做，只是当时被绑死在「插扰动算子」这一个用途上。

## 决定

### 四个动作，顺序定死 remove → add → rewire → set

```
lyflow patch <graph> [--remove-node <id|glob>]... [--add-node <json>]... [--rewire <from>=<to>]...
                     [--set <node>.<param>=<json>]... [--dry-run] [-o <out>] [--json] [--base-dir <dir>]
```

两个脚本做的事拆开来只有这四件。把它们当成动作集而不是「一门改图的小语言」，是因为
**每一个动作都能在不理解算子语义的前提下正确执行**：删节点连带删边、改边的源端口、
加一个节点对象、写一个参数值。桥接层不理解算子语义，这条边界（[ADR-0012](0012-headless-cli.md)、
`docs/architecture.md`）不为 patch 让步 —— 语义那一层的答案仍然只从 core 的 `validate` 拿。

顺序定死而不是按命令行出现的先后，是因为**结果必须只由参数集合决定**，不由打字顺序决定：
同一组动作换个写法得到同一张图，脚本生成的命令行才敢直接用。代价是「先 rewire 再删」这类
组合要写成两条命令 —— 这是刻意的，中间那一步本来就该被人看一眼。

`--rewire a:out=b:port` 的语义是**所有从左端口出发的边改为从右端口出发**，与 `perturb::insert_after`
的那半段图手术是同一件事（`patch.rs` 里重写了一遍参数解析，图上的动作是一样的）。
它只改边，不动图级 `outputs`：`outputs` 是宿主按名字取值的契约，改它是另一个决定，
左端口上挂着图输出时 stderr 会说一句而不是替人做主。

### 幂等：三种「什么都不用做」是 no-op，不是错

- `--remove-node` 匹配不到任何节点 → no-op；
- `--rewire` 的左端口没有任何出边（跑过第一遍之后正是这个形态）→ no-op；
- `--set` 的值与图里已有的值相同 → no-op。

每一条都在 stderr 说明，并进 `--json` 的 `noops[]`（带 `action` / `spec` / `reason`）。
所以**同一条命令跑两遍，第二遍 `applied` 全空、`diff.empty` 为 true**，`lyflow diff <第一遍> <第二遍>` 为空。

这不是洁癖。它是「改一处 → 全量重跑 → 证明只有该动的那几格动了」这种工作法的前提：
命令能重跑，才能把它写进脚本、写进 CI、让另一个人照着再跑一遍得到同一张图。
全是 no-op 的**原地**覆写干脆不落盘 —— 内容一个字节都不会变，但会动 mtime，而编辑器与 watcher 盯的正是 mtime；
给了 `-o` 就照写，那是「我要这个文件」。

**`--add-node` 的 id 撞了是错，不是 no-op。** 「这个 id 已经被占了」与「我要的那个节点已经在了」
是两件事，猜错的代价是悄悄拿别人的节点当自己的。

### dry-run 输出的差异与 `lyflow diff` 逐字相同

`--dry-run` 不写文件，stdout 是**与 `lyflow diff` 同一份实现**（`cli::diff_docs` / `cli::render_diff`）
渲染的结构差异；`--json` 时同一份差异对象出现在 `patch_result.diff` 里。

一份实现两个入口，是因为这两处一旦分叉，「dry-run 说要改的」和「diff 说改了的」
就会在某个边界上不一致，而那时没人知道该信哪一个 —— 与 ADR-0012 里「CLI 不自己写一遍图的加载与校验」
是同一条理由。

### 每步之后过形状校验，最后过 core `validate`；任一步不过整体不写

结构校验是 `graph.rs` 那一层（重复 id、悬空边、自环、输入端口单连接），报错时说明是哪一个动作之后坏的；
core 的 `validate` 是权威那一层（算子、参数、端口类型、必填输入）。两层都过才落盘。
落盘本身先写同目录的临时文件再改名 —— 写了一半的图比没写更糟，原地覆写时尤其。

**图级 `outputs` 还指着的节点不给删**，报错并整体不写。静默把一个图输出删掉，
宿主那边表现为「某个读数突然永远缺失」，是最难回溯的一类改动。

这三条合起来才让 dry-run 有意义：一个「看上去能改、写下去才发现不合法」的 dry-run 不如没有。

### MCP `patch_graph` 的 `dryRun` 默认 **true**

一个能原地覆写图文件的工具，默认必须是「先给我看差异」。`out` 要配 `dryRun: false` 才给过，
否则报错 —— 「我以为它写了」是这套工具里最贵的误解。

## 后果

**bridge 现在会改写图结构了。** `lib.rs` 顶上那句「不改写图结构」指的是**隐式**改写
（[ADR-0002](0002-graphdoc-as-source-of-truth.md)：`load_graph` 只把迁移当诊断报出来，不替用户写回）。
`patch` 是用户敲的一条命令、有 dry-run、有回执、不过校验就不写 —— 它是显式的，不违反那条边界；
`perturb` 从 M5 起已经在做同一件事。

**四个动作不够用的地方，第一版不补。** 没有 `--connect`（新加一条边），
所以 `--add-node` 只对「不需要输入的源算子」单独成立，别的情况要配 `--rewire`
把已有的边挪过去。真实那张图上的结论：把 12 个 `flow.fallback` 短接到主路径 + 删掉整条 b 分支，
两条命令做完（先 12 条 `--rewire`，再 `--remove-node 'n_fb_*' --remove-node 'b_*'`），
一条命令写不下的原因正是上面那条「顺序定死」。等到真的有人被 `--connect` 卡住再加。

**glob 只对节点 id，且大小写敏感**（m6-plan §10 第 6 条）—— `wildcard_match_cs`（`eval.rs`，
`*` 与 `?`，与文件名那份共用同一个 glob 引擎，但另起一个函数）。节点 id 是图里写死的标识符，
`N_FB_*` 与 `n_fb_*` 是两个不同的选择，让它们互相匹配只会让 `--remove-node` 悄悄多删一批 ——
而多删一批比少删一个难发现得多，是这份 ADR 从第一条就在防的那类事故。`b_*` 是真实图里那条
备用分支的命名约定，这个能力就是为它加的。

文件名那份（`eval` 的 `--pattern`，`wildcard_match`）**保持不敏感**，因为采集端在不同版本里
写过 `Master` 也写过 `master`，那不是用户能控制的 —— 两者要分开的原因也在这里：
节点 id 的大小写是图作者说了算的选择，文件名的大小写是采集设备说了算的历史，同一套敏感性
套两边必然委屈其中一边。

**新节点没给 `ui` 时放在图里现有坐标的右下角外面一格**（+260 / +140，一次加多个沿对角线排开）。
坐标是 UI 字段，不影响执行；放在那里只是让人打开图之后找得到它，而不是叠在原点上。
