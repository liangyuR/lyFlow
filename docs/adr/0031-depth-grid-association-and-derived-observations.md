# ADR-0031：深度栅格关联与派生观测

- 状态：已采纳
- 范围：P2阶段5，C01与B07几何投影/裁云组合

## 问题

现有PointCloud是带进程内ID的原生坐标/可选通道数组，没有width/height，也不隐含相机、组织网格或坐标帧。仅将云投成图或将灰度滤波用于深度，无法保留遮挡、缺测、补值以及二维实例与原点的关系。新增功能不能把JSON数组当作原生大载荷，也不能使滤波输出继续混入已替代的噪声点。

## 决定

复用PointCloud、Image、Tensor、Indices与小型Record，不增加C ABI数据种类或结构字段。一个有标定的栅格视图以同次输出的cloud、depth、status、indexMap和vision.DepthMapping.v1为整体契约：

- depth为单通道float32米值；透视深度是相机Z，正交高度可为零或负，不能用数值零代替有效性。
- status为独立u8标记，区分观测支持、插值、滤波与碰撞；无效像素有明确零深度和-1索引，消费者按状态位判断，不从数值猜测。
- indexMap为原生HW float32 Tensor，只保存受点数上限约束、能精确表达的整数点索引；逐像素关联当前cloud。尺寸、来源ID、通道、状态和值必须一起验证。
- Record只保存栅格尺寸、scale、帧、单位、标定/刚体、运行时云引用及载荷配对摘要；摘要用于发现混接，不作为产品身份、图像身份或安全认证。

imageFrame是二维像素帧，gridFrame是投影所用三维帧，cloudFrame是输出云三维帧。相机标定的frame描述三维相机帧；不能要求它与imageFrame相同。gridToCloud明确连接两个三维坐标系。透视K/D使用原图像素中心，工作像素与原像素遵守既有半像素缩放契约；正交原点/分辨率同样明确表示像素中心。

## 观测与来源

投影选出真正可见的代表点，主cloud和indexMap形成可直接消费的紧凑视图；sourceCloud单独保留原云。父源索引与父云引用使用独立原生sourceIndexMap和小型来源信息，未投影/遮挡/非法点状态不伪装成新观测。

深度滤波交付实际处理后的新云和重绑索引，删除无效/去除点，不将旧噪声点与替代点一起作为过滤结果。未变化观测保持原XYZ和可选通道；变化值的重建与补点遵循显式射线/栅格规则，并有独立状态。填洞保留原观测、追加派生点，补点掩膜和索引明确表达插值性质。新数据使用新云ID，旧Indices不能继续指向修改后的云。

无关联点的孔洞不生成虚假的原点。法线、颜色和强度的继承或估计策略分别声明；正常输出不表示补值成为真实测量。父索引仅是原像素关联，不将邻域滤波的一个索引冒称为全部贡献点的来源。

## 消费与验证

ROI/实例掩膜提取、缺陷与截面必须验证完整关联，按indexMap访问真实点并保留可选通道。遮挡、同像素多点、非中心投影、不同RGB/深度分辨率、原始/补值边界、跨帧、空结果、预算和取消分别回归。孔洞、缺测和不充分支持不能被报告为生产合格。

C ABI与C++/Rust接口仍读取同一原生载荷。跨运行比较时运行时云ID本来可以不同；先在每次运行内部验证绑定，再比较几何、通道、索引值和稳定业务元数据，不把ID强行变成持久身份。

本决策不创建Mesh拓扑、设备采集协议或现场质量保证。具体可执行模式、参数和回归以本阶段算子文档、manifest与测试为准。
