# ADR-0010：子图靠编译期展开，不靠嵌套执行器

日期：2026-09-06（M4）　状态：已采纳

## 背景

交互清单把子图（P2 #31）列为「全项目最贵的一块」，理由是嵌套序列化、端口提升、
跨层引用和跨层缓存键。M4 要把它做出来，同时不能把执行器搅浑。

一个能跑的图必须能回答三个问题：**哪些节点可以并行**、**哪个结果可以复用**、
**这一条错误该标到哪个红框上**。执行器目前对这三件事的回答都建立在「图是平的」之上：
拓扑序是一维的、cacheKey 是节点的上游内容哈希、诊断挂在节点 id 上。

## 决定

**子图在 C++ 的 compile 之前被递归展开成平图。执行器、结果仓、事件流对子图一无所知。**

具体四条（m4-plan §0 的 F1–F4）：

1. **展开在 validate 之前**。`parseGraph` → `expandGraph` → `buildPlan` → `execute`，
   中间那一步是 M4 唯一新增的阶段，前后两侧都没有改。
2. **展开后的节点 id 是路径**：`outer/inner/leaf`，事件里的 `nodeId` 就是它。
   `localId` 的字符集（`[A-Za-z0-9_.:-]`）本来就不含 `/`，所以路径可以无歧义地反解。
3. **子图定义存在 GraphDoc 的 `subgraphs`**，节点用 `op: "sub:<id>"` 引用；
   **库算子**是存成独立文件（`*.lyflow-op.json`）的同一份结构，由 C++ 扫描目录注册成
   普通算子 `lib.<id>`。
4. **对外参数是提升出来的**：`{ name, ...Param 字段, binds: [{node, param}] }`，
   一个外参可以绑多个内参；展开时把外参的值写进内参。

## 后果

**白拿到的东西。** cacheKey 自动按内部节点算，所以「改一个提升参数只重算受影响的
内部节点」不需要写任何新代码；并行调度、bypass 透传、`Run to node`、结果仓、
二进制点云全部原样成立。M4 的 C++ 新增只有 `exec/subgraph.cpp` 与 `exec/library.cpp`
两个文件，`executor.cpp` 只改了三行（换成 `prepareGraph`）。

**代价一：诊断落在展开后的节点上。** 子图内部一个参数写错了，诊断的 `nodeId` 是
`outer/inner`，不是 `outer`。前端按当前所在层级的前缀聚合，所以在顶层看到的是
「这个子图节点红了」，进去之后才看到具体是哪个内参。这比「在顶层就精确到内参」差，
但比「让执行器理解层级」便宜太多。

**代价二：子图节点自己不在计划里。** 它没有 cacheKey、没有 `node_state` 事件、
`lyflow_output_cloud` 也查不到它。前端要看子图的输出，得先顺着 `outputs[].from`
解析到产出它的那个叶子节点（`lib/subgraph.ts` 的 `resolveOutput`）。

**代价三：静音一个子图 = 静音它整棵子树。** 展开时把 `bypass` 沿路径传下去，
每个内部节点各自按 E5 的规则透传。对线性子图这正是期望行为；对内部有分叉的子图，
每个输出取「第一个类型兼容且已连线的输入」，与单个节点被静音时的规则完全一致。

**递归与深度。** 展开时维护一个「正在展开的子图 id」栈，重复出现就报
`recursive_subgraph`；深度上限 32。两者都是整图级失败 —— 一张展不开的图，
「哪些节点会重算」本来就没有答案。

**库算子的 compute 是个桩。** `Registry::validate()` 要求每个算子有 compute，
而库算子在展开阶段就消失了。给它一个返回 `internal` 错误的桩函数，
既满足自检，又能在「展开漏了」时立刻炸出来而不是静默产出空结果。

**注册表会在运行时变。** `lyflow_set_library_dirs` 重建注册表的后半段，
这会让已有的 `OperatorDesc*` 失效。约定与热重载（ADR-0009）完全一致：
调用前调用方必须放掉所有 `RunHandle`。

## 备选方案

**嵌套执行器**（子图是一个会递归调 execute 的算子）。好处是子图的边界在运行时仍然
存在，诊断和事件天然带层级。坏处是：并行调度要跨层做，cacheKey 要定义跨层的组合规则，
取消要逐层传播，结果仓要处理嵌套作用域 —— 每一条都是执行器里最难写对的部分再来一遍。
拒绝。

**在前端展开**（把平图发给 C++）。桥接层和前端都不该改写图结构（architecture.md），
而且 headless CLI 与桌面必须走同一条路径。拒绝。

**把子图做成第一类算子（像 Blender 的 Node Group）**，即在注册表里注册一个真的算子。
`sub:` 的定义随文档走，注册表是进程级的，两者的生命周期对不上。库算子走的正是这条路
（它的定义确实在进程级的目录里），文档内的子图不行。
