# glue 主线集成验收

本轮基于主线 `362a6d5`，从原 `feat/glue`（`d65de45`）迁移领域算子。保留主线 Image ABI v15、共享图像缓冲、u8/u16/f32 数据域及现有编辑器；不合入旧 G1 平台实现。

## 本轮实现

- `packs/glue` 默认关闭，包含胶路、胶宽、断胶、边距、判定、人造断胶，以及飞拍 `glue.locate` / `glue.station_calipers` 共 8 个算子。
- `std-image` 增加 `image.board_calib`、`image.load_calib`，统一经 `lyflow_opencv_support` 链接 OpenCV。`io.load_image` 默认文件行为保留，新增 `source=inputs` 接收上游或宿主内存注图。
- 纯色及标准差不足 1 灰度级的模板返回失败位姿，避免 OpenCV 对常量模板给出 NCC=1。胶边超出卡尺窗口返回 `incomplete_bead`，不再返回带空胶宽的 `ok` 或把窗口边缘当胶边。
- 旋转精调先初始化粗扫分数，避免首次比较读取未初始化的栈内存；增加 ±0.12° 的小角度回归。
- 空/非法站点文件、错误位姿、错误标定 Record 类型、非法棋盘尺寸有定位到字段/端口的错误。图像需要全分辨率 u8（灰度、RGB、RGBA）；不将 u16/f32 内存误读为 u8，不把缩小预览当正式测量。
- 实际随包飞拍图通过 C ABI 注入带行填充的相机缓冲、绑定模板/测量点/标定参数，读取毫米点表。连续的有工件/无工件帧验证缓存不会串帧。

## 定位质量门（2026-10-20，`glue.locate` 1.1.0，glue-plan K2）

GlueSight「特征定位 + 示教胶路判胶偏」的 L1：定位失败要说得出原因，贴边、歧义的匹配不能当成功。

本节按时间顺序记了五轮修改，前面几小节的个别说法被后面的小节改掉了（就地标了「后改」）。1.1.0 的最终行为以
`packs/glue/algo/flyshot.h` 里 `locateTemplate` 的注释、`packs/glue/README.md`「失败语义」「角度」两段与 op.doc 为准，要点：

- 质量门与原因码顺序：`flat_template → out_of_image → low_score → at_search_edge → at_angle_edge → ambiguous`；`maxPeakRatio` 默认 1 不判。
- 模板文件：示教框四边各外扩 `templatePad` px 裁下（新示教取 4，0 = 旧模板），`anchor` 是示教框左上角；外圈只给预平滑当真实邻域，
  匹配、各道门、`teachCenter`、`templateSize` 都只按示教框算（最后一小节）。
- 角度：搜索区与模板同样 σ = 1 px 预平滑（模板连外圈整块平滑后裁回示教框、示教框不裁边），每个角度（含 0°）同一条三次插值路径、对齐到同一个亚像素相位、按插值峰顶比分；
  粗扫 ±`angleRange`（`angleRange` < `angleStep` 时按 `angleRange` 一步），护栏在 ±(n·step + `angleStep`)，细扫 step/4、落在窗口两端时外补一个再做抛物线。
- 看不出角度：`angle` 0、`angleObservable = false`、位置取 0° 上的平移；最高分落在护栏上、比 0° 高出差值门限的 1/8 时判 `at_angle_edge`（`angle` 报细扫出的角度）。
- `angleRange = 0` 与看不出角度时最终匹配不挪相位，半像素平移的中心有约 0.1 px 的峰值锁定偏差（1.0.0 也有）。
- 相对 1.0.0 的行为变化见下面第一小节的「行为变化」与「角度」小节的「行为变化」两条。

### 本轮实现

- `glue.Pose2D` 增加 `peakRatio`（最终角度的搜索窗里主峰之外最高的独立峰 / 主峰分数；独立峰 = 突起度 ≥ 0.02 的局部极大，
  主峰自己的侧坡再宽也不算；没有别的独立峰时为 0，主峰分数 ≤ 0 时为 1）、`reason`（成功为空）、`maxPeakRatio`；`message` 仍是给人看的中文。
- 新参数 `maxPeakRatio`（0…1，默认 1 = 不判）：`peakRatio` 超过它判 `ambiguous`。
- 两道贴边门总是开着：峰离搜索窗边 ≤ 1 px 判 `at_search_edge`（实际可用偏移约 `searchRadius` − 2）；角度在 ±`angleRange` 两端外各多扫一步作护栏，
  细扫后的转角超出 ±`angleRange` 判 `at_angle_edge`。圆孔这类旋转对称的模板各角度分数差不出来（最高与最低分之差 < clamp(4 ×（1 − 最高分）, 0.004, 0.02)），
  不判 `at_angle_edge`，角度报 0、`angleObservable = false`（见下面「角度」一节）。（后改：看不出角度、最高分却落在护栏上时也判 `at_angle_edge`，见「亚像素相位」一节第 4 条。）搜索窗形状不变。原因码按 `flat_template → out_of_image → low_score → at_search_edge → at_angle_edge → ambiguous` 取先命中的。
- 示教框离图边不到 2 px 判 `out_of_image`：这时连零位移的峰都落在被图边裁过的窗边上，与真值出图分不开。宿主保存夹具时应拦下这种框。
- `searchRadius` 下限从 1 提到 3：1 左右的窗里没有不贴边的位置，每帧都会判 `at_search_edge`；低于 3 的图加载期就报参数越界。
- **行为变化**：1.0.0 下峰贴边、分数够的帧算成功（合成图上真值出窗 4 px 时贴边匹配分数 0.98），1.1.0 判失败；示教框贴着图边的判 `out_of_image`；
  转角超出 ±`angleRange` 不再截在端点上报成功；`angleRange` 小于 `angleStep` 时 1.0.0 一个角度都不扫（只找平移、`angle` 0），
  1.1.0 扫 ±`angleRange`、转出范围判 `at_angle_edge`（「亚像素相位」一节第 3 条）。本小节写的时候「其余默认结果与 1.0.0 相同」，
  后改：预平滑让 `score` 略高、看不出角度的模板 `angle` 报 0、平移只按 0°（「角度」一节的「行为变化」）。
  存了 `opVersion: "1.0.0"` 的图照常加载运行，只出 `version_mismatch` 警告（次版本不同）；随包 `flyshot.lyflow.json` 仍记 1.0.0，经 C ABI 的用例照常通过。

### 角度：每个角度同一条插值路径，看不出角度时只补平移（2026-10-20，仍是 1.1.0）

GlueSight 阶段 0 评测（`ly-gluesight` docs/testing/algorithm-evaluation.md §9.3，locate 1.0.0）：真实帧只加噪声、不转时角度误差中位
σ = 3 时 0.36°、σ = 6 时 0.63°；三对复拍（真实转角≈0）估出 0.41…0.60°，定位后的胶偏比不定位还差；`angleRange = 0` 时这些误差消失。
原因在 `matchAt`：0° 直接用原图，其他角度经双线性 `warpAffine`，插值相当于轻微平滑，噪声下非零角度的 NCC 反而更高。

- 搜索区与模板先做同样的 σ = 1 px 高斯平滑（浮点上做；核半径 4σ；搜索区按外扩 4 px 的一块平滑再裁回，模板平滑后四边各裁 4 px，
  剩下的与图上同一处平滑出来的完全一样，中心不变；后改：裁边会裁掉贴框边的特征，改为整块平滑、不裁，见「亚像素相位」一节第 2 条）。每个角度（含 0°）都走同一次三次插值 `warpAffine`。只加同一条路径不够：
  0° 的单位变换就是原样拷贝，别的角度仍被插值平滑；先平滑掉单像素噪声，插值才几乎不改变图像。双线性 + 预平滑仍有残差（样本集 σ = 6 P95 0.46°），
  三次插值 + 预平滑降到 0.06°。旋转与 NCC 只算盖住搜索窗的那一块（以前整块搜索区都算），抵掉了三次插值的开销。
- 看不出角度（粗扫最高与最低分之差 < clamp(4 ×（1 − 最高分）, 0.004, 0.02)，阈值不变）时 `angle` 报 0、`angleObservable = false`，
  位置取 0° 上最好的平移；看得出时 `angleObservable = true`。`angleRange = 0` 不扫角度，恒为 true。
  **杠杆臂长的宿主必须把 `angleObservable = false` 当作「转角没补偿」处理**（报定位不足，或只在杠杆臂允许的转角误差内采信），不能当成「零件没转」。
  MCP 的 `glue.Pose2D` assessment 带 `angleObservable`。
- 阈值复核：预平滑后合成圆孔模板的分数差只剩 0.00015 左右（之前 ≤ 0.0036，是插值造出来的），离 0.004 很远。样本集 36 个选中的 96 px 模板里
  5 个（S003/S036、S011、S019、S028）差 0.001…0.004，加不加噪声、转不转都判看不出；其中 S028 整图转 ±1…2° 时照估的角度误差到 0.4…0.67°，
  其余 ≤ 0.25°。复拍 S002→S035、S003→S036 差 0.0037 / 0.0022，照估会报 0.25°，只找平移更准。下限降到 0.002 会让这两对报出 0.25° 的假角度，
  所以不动。

### 亚像素相位、模板不裁边、小角度范围与看不出角度时的转角贴边（2026-10-20 复审，仍是 1.1.0）

复审指出上一节的四个问题，都在 2026-10-17 样本集（只读）与合成帧上复现：

1. **亚像素相位。** 上一节只去掉了噪声那一半：NCC 只在整像素上取分，物体落在半像素上时峰值被压低，压低多少随角度变
   （转过去的位置的小数部分随角度变），无噪声、只平移半像素、不转的合成帧（96 px 模板）仍报 0.25…0.44°、`angleObservable = true`；
   上一版对 S001→S034 的 0.49° 也是这个原因。改法两处一起用：
   - 扫角度前先在 0° 上找一次平移，转过的图再挪一个亚像素量，让这个位置转过去后落在整像素上，各角度（含 0°）都在同一个相位上比；
     粗扫之后改按最好的那个粗扫角度上的位置对齐（零件转了时 0° 上的位置估得偏一点）；
   - 比各角度时用两个方向的三点抛物线插值到亚像素峰顶的值，不用整像素上的值。
   只用前一样，合成图上 220 px 模板转 1.5° 差 0.11°（估计位置的那点误差在峰尖的角度上扣分更多）；只用后一样，半像素帧中心仍偏 0.12 px。
   `score` 仍报整像素上的值。
2. **模板不裁边。** 预平滑后模板四边各裁 4 px，离框边 < 4 px 的特征被整个裁掉，只剩平滑的尾巴，平移漂 1.2…1.9 px 还照常成功
   （1.0.0 是 0.01…0.13 px）。改成模板整块平滑、框外按框边像素延伸（`BORDER_REPLICATE`）、不裁：框外真实邻域与框边一样时与图上同一处平滑出来的一样，
   否则只差框边 4 px 里的平滑尾巴，不偏峰。代价：无噪声、零位移帧上的中心误差 P95 从 0.02 px 升到 0.05 px。
3. **`angleRange` 比 `angleStep` 小**（如 0.4° / 0.5°）时一个角度都不扫，判不了 `at_angle_edge`，却报 `angleObservable = true`。改为按 `angleRange` 一步扫。
4. **看不出角度的分支绕过 `at_angle_edge`。** 角度约束弱的模板真转出范围时，各角度分数差仍不过门限，取 0° 的平移报成功，中心偏 7.5…12.7 px
   （样本集 +4° 时 1–2/36 张）。改为：最高分落在护栏角度上（±(n + 1)·step）、又比 0° 高出差值门限的 1/8（门限 0.004 时为 0.0005）时判 `at_angle_edge`
   （`angleObservable = false`，`angle` 报细扫出的角度）。合成圆孔各角度分数差 0.00004…0.00015，离 0.0005 远；样本集 S011 / S019 / S028 转 +4° 时高出 0.0007…0.0027。
   其余看不出角度的帧仍报 0、位置与 `angleRange = 0` 的结果相同（最终匹配不挪相位）。

### 小角度范围的护栏、细扫两处与半像素用例（2026-10-21 复审，仍是 1.1.0）

1. **`angleRange` 很小时护栏跟着缩。** 上一版 `step = min(angleStep, angleRange)`，护栏在 ±(n + 1)·step，`angleRange` = 0.1° 时只扫到 ±0.2°；
   看不看得出角度的门限是绝对的（≥ 0.004），扫的范围这么窄，220 px 合成模板（`angleRange` = 3° 时转角误差 ≤ 0.05°）也判看不出角度，
   转 +1.1°、+1.5°、−1.3° 照报成功（只补平移，中心偏 1.2…1.8 px），−0.7°、+0.6° 却判 `at_angle_edge`，不单调；`angleRange` = 0.05° 时转到 ±2° 都报成功、偏到 2.6 px。
   改为：范围内仍按 `angleRange` 一步，护栏放在 ±(n·step + `angleStep`)，总比端点多出一个 `angleStep`（`angleRange` ≥ `angleStep` 时就是原来的 ±(n + 1)·step，不变）。
   同一网格（10 个转角 × 3 个亚像素平移）上：`angleRange` = 0.4 / 0.2 / 0.1 / 0.05° 时转 ≥ 0.6° 的帧全部判 `at_angle_edge`；
   仍报成功的只有离端点不到一个 `angleStep` 的 0.2°、−0.25°（`angleRange` 0.1 / 0.05°，看不出角度、只补平移，中心误差 ≤ 0.36 px）——
   这么小的转角在这个模板上本来就差不出 0.004 的分数，与 `angleRange` = 3° 时看不出角度的帧同一种处理。真值正好在端点 0.2° 上的一帧细扫出 0.211°、判 `at_angle_edge`。
2. **细扫中间那个角度的相位。** 细扫五个角度时中间那个沿用粗扫的分数，那是按 0° 上的位置对齐的相位，另外四个按粗扫最好角度上的位置对齐，

3. **细扫窗口两端不做抛物线。** 最好的细扫角度落在 ±2·step/4 上时不做抛物线，真实转角离粗扫角度 0.375…0.5 步时角度量化到窗口端点

   默认 ±3° / 0.5° 下上述网格的角度误差最大值 0.050° → 0.027°，这三个转角 ≤ 0.015°。
4. **半像素用例的理由写错了。** 「只平移 (0.5, 0.5) px」那一帧上一版中心偏 0.12 px，不是假角度带的：`angleRange = 0`、根本不扫角度时也偏 0.12 px，
   角度≈0，是半像素处三点抛物线插值偏向整像素（峰值锁定）。这一版扫角度时最终匹配挪了相位，偏差没了；`angleRange = 0` 与看不出角度的帧
   最终匹配不挪相位，仍有约 0.12 px（1.0.0 也有），记在 op.doc / README / 头文件里，没有改（改了 `angleRange = 0` 的结果就与 1.0.0 不同）。
   用例注释改正；220 px 模板上半像素相位的假角度不明显（去掉相位对齐只差 0.002°，那一例只靠中心容差抓到），另加 96 px 模板的半像素用例防它。

### 模板带外圈：框边预平滑偏置（2026-10-21 复审，仍是 1.1.0）

复审确认的问题：搜索区按外扩 4 px 的一块平滑（真实邻域），模板只有示教框自己、整块平滑时框外按框边像素延伸（`BORDER_REPLICATE`）。
示教框外 1.5 px 内有平行于框边的强边时，图上框边处有那条边的平滑尾巴、模板上没有，平移峰被拉偏，分数仍 > 0.96、照常成功。
合成场景（48 px 框，暗十字 + 暗圆盘，框左、上两边外 gap px 起是暗半平面，σ = 1 噪声，5 个平移）上 dcc726b 的最大中心误差：

| gap（px） | 0 | 0.5 | 1 | 1.5 |
|---|---|---|---|---|
| dcc726b，只找平移 / ±3° | 0.61 / 0.65 | 0.33 / 0.38 | 0.15 / 0.22 | 0.06 / 0.10 |
| `templatePad` = 4，只找平移 / ±3° | 0.16 / 0.22 | 0.12 / 0.16 | 0.09 / 0.16 | 0.04 / 0.08 |

决定（2026-10-21）：发布前修这一项，示教时存带 4 px 外圈的模板，用真实邻域平滑。复审的另两项转角问题按同日决定留作已知问题（v1 只找平移，`angleRange = 0`）。

实现：

- 新参数 `templatePad`（int，默认 0，0…16，高级；产线图 `graphs/flyshot.lyflow.json` 加了同名顶层参数）。模板文件 = 示教图上示教框四边各外扩 `templatePad` px 的一块，
  大小 (w + 2·pad) × (h + 2·pad)；示教框 = 文件去掉四边各 `templatePad`；`anchor` 仍是示教框（不含外圈）左上角，文件左上角在 `anchor − templatePad`。
- 内核先把整个文件平滑（与搜索区同一个核，σ = 1、半径 4），再裁回示教框去匹配。`templatePad` ≥ 4（`kLocateSmoothRadius`）时示教框里每个像素用的都是真实邻域，
  与图上同一处平滑得一样（无噪声、整像素平移时分数 1.00000），这一偏置没了。`templatePad` = 0 时与 dcc726b 逐位相同（旧图结果不变），
  偏置照旧，记在 op.doc / README / 头文件里。
- `templatePad` 为 1…3 是加载期错误（`bad_param`，指向 `templatePad`）：外圈比核半径窄，框边仍要按边延伸，偏置只是变小。
  模板文件去掉外圈后没有示教框（宽或高 ≤ 2·`templatePad`）是执行错误 `bad_param`，指向 `template`。内核直接调时同样情况判 `out_of_image`。
- 图边：原来「示教框离图边不到 2 px → `out_of_image`」不变；另加带外圈的模板（示教框外扩 `templatePad`）放不进这一帧也判 `out_of_image`，
  即示教框离图边至少 max(2, `templatePad`) px。宿主示教时框离图边不到 4 px 就裁不出完整外圈，应在示教时拒绝。
- `flat_template`、`teachCenter`、`peakRatio`、两道贴边门、`angleObservable`、叠画与 Pose2D 的 `templateSize` 都只按示教框算，与以前一样（`templateSize` 不含外圈）。

## 未通过站位的候选胶宽

`glue.bead_width` 的 `bead.stations` 增加与 `count` 等长的 `candidateLo`、`candidateHi`、`candidateWidthPx` 数组。前两项是相对该站 `center` 沿 `normal` 的像素偏移，后一项是两者之差，始终以 px 表示。

通过站位与正式 `lo`、`hi`、`widthPx` 一致。未通过站位的候选必须有完整半高双边、双边位于配置的 `searchHalf` 内且包围期望中心，中心偏差不超过 `max(6 px, centerRatio × 参考宽)`。存在可信示教偏移轨迹时使用轨迹中心及轨迹参考宽，否则使用示教中心与 `widthRange` 上限。满足这些位置条件的候选取最近者，宽度超限仍可保留，不把它改成合格宽度；没有可信双边时三项均为 null。候选只作诊断显示，不能当作合格胶宽，也不能保证排除所有阴影。候选不参与参考宽度、coverage、present、断胶或 NG 判定，也不以邻站插值制造宽度。原正式宽度字段在未通过站位仍为 null。
