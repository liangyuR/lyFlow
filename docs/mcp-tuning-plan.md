# MCP 调参实现计划

基于 main `df2e477`，对应本次确认的六项设计。执行语义与检测算法继续由 core 负责，批评估和真值匹配由 Rust CLI 统一实现，MCP 负责工具、呈现和试验生命周期。

## 完成条件

- [x] P0 参数：validate / plan / run / params / patch / eval 的 graphParams 取值一致；配方与显式覆盖优先级固定；绑定冲突有修正提示。
- [x] P0 检查：get_environment 核对 HTTP / CLI 身份与算子包；inspect_graph 给出拓扑、core 生效值、绑定、外部依赖、参数角色与能力。
- [x] P0 输出：Record / Bundle 字段选择、分页、归约、完整 artifact；执行、量测、判定分别表示。
- [x] P0 看图：Image 与 overlay2d 合成 PNG；原图 ROI、缩放和坐标映射可核对。
- [x] P1 评估：样本 graphParams / truth / tags；漏检、误检、定位/量测缺失、数值/断口误差、时延分位数；缺失原因；按工件固定分组划分。
- [x] P1 记录：冻结图、参数、输入身份、构建身份、划分和缓存策略；基线比较、改善/退化样本、失败证据；候选图/配方导出带评估引用。
- [x] P2 搜索：参数角色与锁定规格、候选生成、敏感度、运行次数/时长预算、任务查询/取消/断点续跑。
- [x] 可靠性：CLI JSONL 流式落盘；超时/取消结束执行、保留部分结果；冷热性能策略清楚。
- [x] 文档：MCP 字段与 CLI 对照、随动/飞拍工作流、测试地图、实现验收。
- [x] 验证：仅用 MCP 完成图检查→调参→批评估→失败叠画→基线对比→导出；不把现场数据缺失或测试跳过记成通过。

## 验证安排

优先扩展已有 MCP graph / argv / cloud / cli / server / smoke 测试与 Rust eval / CLI 测试；数值规则与输出契约有正反例。glue 专项使用现有合成夹具。现场阈值由任务提供，合成结果不代替现场漏检率。

P0、P1、P2 是实现顺序，全部属于完成范围；完成审计逐项记录证据后再关闭目标。


逐项证据与既有失败边界见 [实现验收](mcp-tuning-acceptance.md)。
