## 24. 管理

## 25. 不回归

见页首。开发过程中 e2e 抓到的真问题：① 矩阵 Ctrl+单击赶在一次重渲之前时第二下看不到第一下的选中（改成函数式更新）；② 管理页的左右两栏
被 `styles.panel.css` 的同名规则压成上下两栏（加一级选择器）；③ 单测抓到 schema 里配方名的正则漏了反斜杠。

## 取舍与计划没覆盖的决定

1. **管理动作都只改内存、进撤销栈，Ctrl+S 才落盘**（新建、复制、重命名、删除、设默认、导入、按建议修复）。计划 K6 ③ 说 Ctrl+S
   一次存图和所有改过的配方，K7 说撤销快照内存里的配方集合；把删除 / 改名做成立即的磁盘操作，撤销就得去磁盘上把文件变回来。
   唯一立即写的是**导出**（它不改内存里的集合）。删除仍有确认对话框，存盘前还能 Ctrl+Z。
2. **30 s 自动备份覆盖配方**：配方有没存的改动时，同一拍把整个内存配方集合写进 `<配方目录>/autosave~.json`（每个配方记着对应的磁盘文件），
   并照样写一份 `<图>~`，让开图时的「恢复备份」只问一次、图与配方一起回来；存盘成功或选「不恢复」时删掉。理由是 MERLIC 的教训
   （调研 §2：临时改动丢了）—— 配方改动留在内存里正是 K6 ③ 允许的状态，崩溃时它和图的改动一样值得保。没有逐个配方写 `~` 文件：
   N 个配方会问 N 次，而且目录里多一堆 `~`。
3. **外部修改检测只查配方文件与 `index.json`，不查图文件**。计划「不做」一节说的是配方的多人编辑；图文件的读写经 `load_graph` / `save_graph`
   （有迁移、Rust 侧重新序列化），拿文本比没有意义，而且那是 P3 之外的老行为。检测依据是「上次读 / 写下的文本」，不看 mtime。
4. **配方的身份以文件名为准**：文件里的 `name` 与文件名不一致（手工复制改名）时按文件名认、下次写这个文件时改正。
5. **「改过」的配方记成当前图**：任何一种编辑（改值、修失配、改名）都把配方的 `graph` 换成当前图的 id 与摘要、`updatedAt` 换成那一刻 ——
   它从此是对着这张图维护的，④ 随之消失；只打开、切换、设默认不算。这一步在撤销事务里做，撤销会一起还原。副作用：在编辑器里给图多
   纳入一个参数（摘要变了），没动过的配方都会出现 ④ 的提示，直到改它或「按当前图更新记录」—— 这是「提示，不阻止」的本意。
6. **specDigest 的规范形**（P4 的 Rust 要照着实现，写在 recipe.md §3）：每个图参数 `[名字, type, min, max, options(只取 value、排序)]`，
   按名字码点序，`JSON.stringify`，SHA-256 → `sha256:<hex>`。softMin/softMax、label、单位、group、default 不进摘要（不改变什么值合法）。
   SHA-256 自己写了一份同步实现（`lib/sha256.ts`，对着 `node:crypto` 单测）：失配判定随 doc 每次重算，`crypto.subtle` 是异步的。
7. **失配判定与 core 同一套判据，只对有 `type` 的图参数查 ② ③**（老格式只查 ①，core 也不查它）。每个参数至多一条（① → ② → ③），
   ② 的转换建议转完再夹进限位，所以按建议修一次就干净。enum 不在 options 里归 ③（计划「不满足 options」），类型不对归 ②。
8. **失配阻止运行放在 `startRun`**：①–③ 里多出的名字 core 根本看不见（编辑器只交声明着的），所以不能指望 core 报；界面上的每一种运行
   （F5、节点按钮、实时预览、自动运行）都经它。显式给了 `params` 的运行（宿主、脚本整份替换取值）不受当前配方约束。
9. **「自动运行打开时照常触发运行」**解释为：人切一次配方（下拉框、矩阵列头、管理页）就补一次正式运行；打开图时自动选中默认配方、
   撤销把当前配方撤没了都不算（否则打开一张图就会自己跑起来）。
10. **当前配方按内存身份跟随**：改名、撤销改名时它还是当前配方；被删 / 被撤没了回到「基础」。
11. **图参数改名同步改内存里每个配方的键**（同一步撤销）。计划没写；不这么做的话改完名每个配方都是一条失配 ①。删除图参数照 P1 的取舍 3
    不动配方（成为失配 ①）。
12. **传输层五个方法定为 `Transport` 的必需方法**（Tauri、HTTP 实现，Static 只读：`listRecipeDir` 返回不存在、写删改名抛错）。路径约束两侧一致：
    只认配方目录（最后一段 `.recipes`）里的三种文件与任意位置的 `*.lyflow-recipe.json`，不许 `..`；Tauri 要绝对路径，HTTP 只在工作区里（403）。
    写入先写临时文件再改名覆盖。
13. **对话框画在编辑器里**（`lib/modal.ts`：起名、确认删除、外部修改的三选一），不扩宿主的 `EditorDialogs`：那一套只有文件选择与是 / 否。
    导入导出要选文件，加了可选的 `EditorDialogs.pickRecipePath`（Tauri 壳用 plugin-dialog 实现）；没有它就退回 `pickPath`，再没有就在
    编辑器里输路径（HTTP 宿主）。没有给 Tauri 壳加通用的 `pickPath`：那会让参数表单与 3D 导出也换成原生对话框，m3 的「导出按钮可点」一组
    会被系统对话框卡住。
14. **矩阵的就地编辑不夹限位**：格子里不画滑块、数字框不按 min/max 夹，越界的值照样写进去、单元格标红、由失配报告说原因 —— 这正是矩阵
    「越界为红」要表现的；弹出编辑（向量、颜色、transform、curve、text、flags）用完整控件，照常夹。复制到配方的语义是「目标配方里这个参数
    的有效值等于选中格的值」：选基础列或沿用基础的格子 = 让目标回到基础（删掉覆盖）；同一参数选了多格时拒绝并提示。
15. **Inspector 顶上的图参数简表**（面板关着时）也挂被覆盖的橙色标记与「配方 · 基础 X」，恢复 / 写回基础只在面板里。
16. `snapshot().recipe` 保持 P1 的 `{current, params}`（P1 的 e2e 逐字比它），配方集合另放在 `snapshot().recipes`。
