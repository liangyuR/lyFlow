# 算子边界迁移计划

状态：待实施；本轮仅交付逐项审计及方案。基线 `9940c8c`，不把文档完成记为算法迁移完成。

参见[目标边界](operator-package-boundaries.md)、[逐算子清单](operator-package-audit.md)及[机器清单](operator-package-audit.json)。M0–M7 为本次架构迁移波次，与既有能力补齐计划 P0/P1/P2 的优先级编号无关。

## 每次迁移的执行清单

1. 锁定原ID/版本、参数默认值、端口、单位、坐标系、输入顺序和失败诊断；记录直接后端与当前传递依赖。
2. 先抽可独立链接的内部算法/校验接口，再迁算子注册；不能让一个算子通过执行另一包的节点绕过真实C++依赖声明。
3. 冻结旧→新ID、包、版本及数据映射。纯归属移动不改ID；拆分节点、改变端口/单位必须有迁移诊断和等价性说明。
4. 同步直接消费者、场景图、Bundle/Record schema、片段、库组合和宿主注入。不能只有新生产者没有匹配消费者。
5. 校验正常、空输入、无效/退化、单位/帧不符、取消、异常及只读输入。选定方法、迭代/阈值与重试策略需分别回归。
6. 核对缓存键的算子版本、模型指纹、场景图与内部实现身份；改变数值契约时不沿用旧结果缓存。不能只以包名称变化判断缓存等价。
7. 单独启用目标模块构建，检查导入表、安装文件及许可证，证明轻量配置没有PCL/OpenCV/ORT等意外依赖。
8. 更新本清单归属/状态及来源，不把“source已移动”视为运行与交付验收通过。

## 重点风险与对应验收

| 风险 | 验收 |
|---|---|
| 毫米/米混用或XZ/XY反射被当旋转 | 单位/轴映射夹具、手性检查、原始→公共→原始往返；未知元数据拒绝连接/计算 |
| DTS毫米几何载荷保留默认Meter标签 | seal_dome/pick_metal/seal_root/flush的旧版本夹具按来源适配0.001，独立核对Measurement.unit；不能仅凭unit=Meter跳过转换 |
| 清洗丢失1280槽、排序打乱轮廓、索引不再指向原云 | NaN/缺槽/双层重叠/非单调采样，附加通道及sourceIndices往返；模型前后长度一一对应 |
| TLS替换RANSAC、固定半径/先验/重试被合并掉 | 分方法固定夹具、短弧/退化/双相机异常与质量字段回归，不以名称相同代替算法等价 |
| 纯几何距离误当作间隙或面差定义 | 独立基准和方向、signed/unsigned、左右交换、投影/采样边缘、端点/圆边界分别验证 |
| 有效性、胶路合格和生产许可混为一谈 | 未测得保持无效及reason；候选可见性不改变正式runs/present/coverage或最终业务判据 |
| 包变轻只存在于文档 | core-minimal、profile-metrology、adapters-only、portable-generation独立构建与实际导入表检查 |
| 旧库图表面加载成功但丢端口/参数 | 编辑器与headless使用同一迁移夹具，缺包/旧版保留节点连线，不能迁移的项明确拒绝执行 |
| 相同ID内部实现变化复用旧缓存 | 明确版本/图/模型指纹变更，旧缓存不命中新语义；迁移后重复运行与干净运行一致 |
| SDK通过但依赖开发目录或私有头 | 独立安装目录的C++17/Rust/CLI消费者，源码树外运行；不得依赖另一包的私有实现路径 |

最终编辑器测试继续按功能契约保持100项以下，保留主线94项覆盖并按必要场景合并组织；新增迁移回归不能靠skip、提前return或删除错误分支把数字压低。原生、Python和SDK测试单独统计，静态文档检查不能代替这些执行证据。

## 本轮检查与后续维护

本轮不修改算法、包注册、依赖构建、ABI、用户配置或个人工作流。逐项清单的静态验证检查ID全集、来源、目标、波次、依赖字段和文档链接；这些检查只证明方案完整性及可追溯性。

维护者可对照当前运行库导出的manifest与DTS描述重新检查清单；命令和基线指纹见[审计清单](operator-package-audit.md)。当新增算子、改变端口或修改归属时，应更新该清单对应项，不能继续把本基线的251当作未来固定数量。
